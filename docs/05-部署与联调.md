# 05-部署与联调

> 本文档描述两条链路：**A. 当前阶段验收链路**（virtual-server 转发程序 + gec6818 LVGL 终端 + web 大屏，任务改动.txt）
> 与 **B. 历史网关演示链路**（node-gateway + simulate_devices + web，32 节点，备用）。

## A. 当前阶段验收链路（推荐）

### A.1 角色划分（任务改动.txt）

| 角色 | 运行位置 | 程序 | 职责 |
|---|---|---|---|
| 数据源 + 转发器 | Ubuntu | virtual-server/virtual_bridge.js | 每 3s 生成 4 温区虚拟数据 → 上报华为云 yihao；每 30s 制造一次报警；经 TCP:18830 推 virt_data 帧给终端；接收 confirm/ack |
| 终端 + 报警设备 | ARM Cortex-A53 Linux 板  | device/ui/coldstorage_ui | 接收 virt_data → LVGL 显示 4 温区/曲线/状态；报警时 /dev/beep 蜂鸣 + LED 亮；触摸"取消报警"停蜂鸣并上报 confirm |
| 应用展示 | 任意机器 | web/server.js | H5 大屏展示 1 号冷库数据（REST + WebSocket） |
| 云平台 | 华为云 IoTDA | 设备 yihao | 属性上报接收、命令下发（confirm_alarm/set_beeper/set_led/set_alarm_threshold） |

### A.2 启动步骤

```bash
# 1) Ubuntu：启动虚拟数据转发程序（连华为云 + 监听 18830）
cd virtual-server
npm install
node virtual_bridge.js        # 看到 "MQTT 已连接" 与 "TCP 服务监听 18830"

# 2) 可选：web 大屏（展示 1 号冷库；见 A.4 已知限制）
cd web && npm install && node server.js   # http://127.0.0.1:8080

# 3) ARM Cortex-A53 Linux 板 ：交叉编译并运行终端
cd device/ui && make clean && make LVGL_ROOT=/home/gec/lvgl9
tftp -b 60000 -g -r coldstorage_ui 192.168.44.207   # 从 Ubuntu 下载（IP 按实际）
chmod +x coldstorage_ui
./coldstorage_ui 192.168.44.208 1号冷库 NO.001 -20   # <转发程序IP> 冷库名 编号 阈值
```

### A.3 验收观察点

- 终端顶栏"在线"变绿、4 温区温度每 3s 刷新、趋势图滚动（24h 窗口 60 点）
- 每 30s 一次报警：底部报警栏出现紧急报警、蜂鸣器响、LED 亮、温区卡红框闪烁
- 触摸"取消报警"→ 蜂鸣停止、LED 灭、转发程序日志出现"收到报警确认"
- 云端（IoTDA 控制台）可下发 confirm_alarm / set_beeper / set_led / set_alarm_threshold 命令，终端执行并回 ack

### A.4 已知限制（待办）

1. **web 大屏与华为云无数据通路**：web/server.js 只连本地 aedes broker（127.0.0.1:1883），virtual_bridge.js 只上报华为云。
   若验收要求大屏实时显示云端数据，需实现其一：
   - web/server.js 增加华为云 mqtts 订阅（主题见 docs/03）；或
   - virtual_bridge.js 在 enabled=true 时同时向本地 broker 转发一份。
2. 转发程序单终端语义：server.listen 只保留最新一个 TCP 连接，多终端接入会互相覆盖（当前验收只有 1 台 gec6818，无影响）。
3. 阈值/上报周期按钮：在虚拟数据场景下由转发程序/云端管理，终端本地点击只改显示、下帧即被覆盖（见 docs/09 §五）。

## B. 历史网关演示链路（32 节点，备选）

前置：Node.js ≥ 18。

```bash
# 安装依赖
cd web && npm install
cd ../node-gateway && npm install

# 方式一：一键启动（三个终端窗口）
scripts\start-all.bat        # Windows
# scripts/start-all.sh       # Linux/macOS

# 方式二：手动逐个启动
node web/server.js                       # 1) Web 后端 + broker + 大屏 http://127.0.0.1:8080
node node-gateway/gateway.js             # 2) Node 网关（连接 broker + TCP:18830）
node tools/simulate_devices.js           # 3) 模拟 16 冷库 × 前后 = 32 节点
```

验证：浏览器打开 http://127.0.0.1:8080 → 卡片出现数据 → 点按钮下发 LED/蜂鸣器 → 模拟设备终端显示收到指令并回 ack → 大屏事件日志出现命令结果。

## C. 常见问题

- **broker 连不上**：确认 web/server.js 已启动（1883 端口）。
- **终端显示"离线/--.-"**：确认 virtual_bridge 在跑（Ubuntu 上 pkill -f virtual_bridge 后重启），且 18830 端口通（nc -vz <ip> 18830）。
- **蜂鸣器不响**：确认 /dev/beep 用 ioctl(fd, 0/1, 1) 控制（write 无效，见 buz_test.c）；/sys/class/leds/led1/brightness 写 1/0。
- **大屏无数据（验收链路）**：见 A.4 已知限制；历史演示链路则确认网关与 broker 已连通。
- **真实平台鉴权失败**：deviceId/secret 必须与平台创建的一致；TLS 证书用 conf/rootcert.pem。
