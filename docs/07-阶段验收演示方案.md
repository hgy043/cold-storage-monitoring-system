# 07-阶段验收演示方案（当前链路）

> 本方案对应**任务改动.txt** 的验收要求：ARM Cortex-A53 Linux 板  作终端与报警设备，Ubuntu 接收华为云虚拟数据并转发，
> web 只展示 1 号冷库，虚拟数据每 3s、报警每 30s，LED/蜂鸣联动，巡查确认报警后停蜂鸣。
> （历史 32 节点网关演示方案已移至 docs/05 §B 备用。）

## 1. 演示环境准备（验收前 5 分钟）

| 项 | 要求 |
|---|---|
| Ubuntu | Node.js ≥ 18；virtual-server 依赖已装（npm install） |
| 华为云 | IoTDA 设备 yihao 已创建（deviceId/secret 与 virtual-server/conf.json 一致）；产品含服务 coldstorage（temperature/humidity/led/beeper/alarm/alarm_threshold） |
| ARM Cortex-A53 Linux 板  | 已部署 device/ui/coldstorage_ui（交叉编译产物）；屏 800×480；/dev/beep 与 /sys/class/leds/led1 可用 |
| 端口 | Ubuntu 18830（TCP 转发）、8883（MQTT 上行）；web 8080（可选） |

启动顺序：

```bash
# Ubuntu：启动转发程序（应看到 "MQTT 已连接" 与 "TCP 服务监听 18830"）
cd virtual-server && node virtual_bridge.js

# ARM Cortex-A53 Linux 板 ：运行终端（IP 为 Ubuntu 实际地址）
./coldstorage_ui 192.168.44.208 1号冷库 NO.001 -20

# 可选：web 大屏（1 号冷库；数据通路见 docs/05 A.4 已知限制）
cd web && node server.js   # http://127.0.0.1:8080
```

> 兜底自检：终端顶栏"在线"变绿、温度每 3s 变化；转发程序日志有"推送虚拟数据"（每 30s 一条）。

## 2. 演示流程（建议 10~15 分钟）

### 2.1 架构讲解（2 分钟）

- 华为云 IoTDA 设备 yihao ← virtual_bridge（Ubuntu）每 3s 属性上报；virtual_bridge 同时经 TCP:18830 推 virt_data 帧
- ARM Cortex-A53 Linux 板 ：LVGL 800×480 SCADA，5 页触摸（主菜单/实时监测/温区总览/设备控制/能耗与设置）；报警器（蜂鸣 + LED）
- 数据闭环：云端虚拟数据 → 转发程序 → 终端显示/报警 → 巡查确认 → confirm 帧 → 转发程序停止报警
- 命令闭环：云端命令（confirm_alarm/set_beeper/set_led/set_alarm_threshold）→ 转发程序 cmd 帧 → 终端执行 → ack 回执

### 2.2 实时监测展示（3 分钟）

1. 实时监测页：24h 趋势图（4 温区曲线滚动，60 点）、4 温区当前值卡（点击图例切换曲线显隐）
2. 温区总览页：4 温区大卡（温度/湿度/设定/状态灯），异常红闪
3. 能耗与设置页：实时功率/耗电量/设备状态（除霜、风扇、门）、阈值与周期按钮
4. 设备控制页：制冷流程动画（流动圆点沿管线循环）、频率/电流/排气/吸气参数波动

### 2.3 报警联动闭环（4 分钟）——核心验收点

1. 等待（或等待）30s 报警周期：某温区温度越限 8~14℃，转发程序制造 status=2 报警
2. 终端表现：底部报警栏出现"紧急"报警、蜂鸣器响、LED 亮、温区卡红框闪烁、报警计数 +1
3. 巡查人员到场 → 触摸底栏"取消报警"按钮 → 蜂鸣停止、LED 灭、报警栏转"无报警"
4. 转发程序日志出现"收到报警确认"，30s 后再次制造下一次报警
5. 强调：报警一直响到**人工确认**为止——这是"终端即报警设备"的验收语义

### 2.4 云端命令（3 分钟）

华为云 IoTDA 控制台（或 API）下发：

| 命令 | 预期 |
|---|---|
| confirm_alarm | 终端停蜂鸣/灭 LED，转发程序收到确认 |
| set_beeper {on:1/0} | 终端 /dev/beep 响/停 |
| set_led {on:1/0} | 终端 LED 亮/灭 |
| set_alarm_threshold {value:-25} | 终端阈值显示更新（数据源以云端为准） |

### 2.5 工程化要点（2 分钟）

- 协议：docs/02 §4.3/4.4 virt_data/confirm 帧（一帧一行 JSON，\n 分帧）
- 线程模型：TCP 接收线程（数据/报警）与 LVGL 主循环分离，共享快照互斥锁保护
- 声光执行：/dev/beep ioctl(fd,0/1,1)；/sys/class/leds/led1/brightness 写 1/0
- 可靠性：终端断线指数退避重连、确认后 6s 锁存防报警回响、转发程序断线重连 MQTT

## 4. 评审常见问题与回答（Q&A）

**Q1：虚拟数据如何保证"真实感"？**
A：4 温区围绕设定值（-25/2/10/15℃）随机游走 + 均值回归，湿度按冷冻/冷藏/预冷/穿堂差异化（52/72/78/66±5），
   室外 28~34℃；能耗按温度模拟功率/电量累加/化霜周期。

**Q2：报警为什么每 30s 一次？**
A：任务改动要求"虚拟数据每 3s、报警每 30s"；确认后立即重置计时，保证演示节奏可控、可重复。

**Q3：为什么终端是报警设备而蜂鸣由确认停止？**
A：验收语义是"报警必须人工到场确认"（安全巡查），终端点"取消报警"或云端 confirm_alarm 命令二选一，
   确认后终端上报 confirm 帧，转发程序停止报警状态，避免无人值守时蜂鸣器长响。

**Q4：断线/异常怎么办？**
A：终端重连指数退避（1→128s，见 docs/09 §五已知边界）；转发程序 MQTT 每 3s 自动重连；
   确认后 6s 锁存窗口吸收在途报警帧，防止蜂鸣回响。

## 5. 验收避坑指南

1. **转发程序必须真实连上华为云**：确认日志 "MQTT 已连接"；连不上时检查 conf.json 的 host/port/deviceId/secret/clientId。
2. **板子显示离线**：Ubuntu 防火墙放行 18830（ufw allow 18830）；`nc -vz <ubuntu-ip> 18830` 自测。
3. **蜂鸣器不响**：/dev/beep 必须用 ioctl 控制（write 无效）；确认 buz_test.c 可用后检查权限。
4. **报警不自动出现**：确认 virtual_bridge 在跑（pkill -f virtual_bridge 后重启）；报警周期 alarmEveryMs=30000。
5. **web 大屏无数据**：见 docs/05 A.4（web 与华为云之间尚无自动数据通路，需先实现其一）。
6. **验收节奏**：先让系统跑 2~3 分钟攒趋势图数据，再开始正式讲解。
