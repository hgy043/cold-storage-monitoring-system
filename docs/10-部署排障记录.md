## 一、编译/构建类（6 项）

| # | 问题 | 原因 | 解法 | 状态 |
|---|---|---|---|---|
| 1 | gateway 编译报 `hw_type.h: 没有那个文件或目录` | SDK 相对路径少一级：`gateway/` 在 `冷库监控系统/` 内，SDK 与其同级，应 `../../` 而非 `../` | 改 4 文件共 7 处（Makefile / gateway.c 的 SDK_WORK_PATH / start.sh / README.md），统一为 `../../huaweicloud-iot-device-quickstart` | ✅ 已入仓库 |
| 2 | device/ui 报 `lv_drivers.mk: 没有那个文件或目录` | Makefile 用 `$(abspath)` 展开含空格的路径（"deepseek harness"），make 按空格分词 | 建无空格符号链接 `ln -s ... /home/gec/lvgl9`，编译时 `LVGL_ROOT=/home/gec/lvgl9 make` 覆盖 | ✅ 部署解法（代码保持默认路径） |
| 3 | 链接报 `R_ARM_MOVW_ABS_NC ... recompile with -fPIC` | Ubuntu gnueabihf 工具链默认开 PIE | 链接加 `-no-pie` | ✅ |
| 4 | make 显示"无需做任何事"，产物却是 0 字节 | 失败链接留下的空文件 mtime 比 .o 新，make 跳过 | `rm -f coldstorage_ui` 后重新链接 | ✅ |
| 5 | 链接报 `uses VFP register arguments ... does not` | LVGL 工程里 458 个旧软浮点 .o 的 mtime 比源文件新（hgfs 共享文件夹时间戳不可靠），make 跳过重编，新旧 .o 混合 ABI | `find . -name "*.o" -delete` 全量重编 | ✅ |
| 6 | device（软浮点）与 coldstorage_ui（硬浮点）ABI 不匹配 | 两套工具链默认 ABI 不同：厂商 arm-linux-gcc 5.4.0 = soft，apt gnueabihf = hard | 全部改用厂商工具链重编；验证 `/lib/ld-linux.so.3`（软浮点动态链接器） | ✅ |

## 六、部署流程要点（结合上述坑）

1. **目录结构**：`deepseek harness/` 下 SDK 与 `冷库监控系统/` 同级；`gateway/` 内所有 SDK 相对路径为 `../../huaweicloud-iot-device-quickstart`，必须在 `gateway/` 目录内运行（IOTA_Init 读 `conf/rootcert.pem`）。
2. **含空格路径**：device/ui 的 Makefile 默认路径含空格时，用符号链接 + `LVGL_ROOT=` 覆盖。
3. **工具链 ABI**：device、device/ui、LVGL 全部用同一套厂商工具链（arm-linux-gcc 5.4.0 soft float）；Ubuntu apt 的 gnueabihf 是 hard float，混用必崩。
4. **陈旧 .o**：共享文件夹拷贝源码后先 `find . -name "*.o" -delete` 再 `make clean && make`，避免时间戳陷阱。
5. **网络**：虚拟机用 NAT 或固定桥接 IP；华为云 MQTT 端口 8883 需能出网 + DNS 正常。
6. **认证**：改 `gateway/ClientConf.json`（不是 SDK 目录的示例）；deviceId 的 `产品ID_设备标识` 必须与平台注册一致，secret 填真实密钥。
