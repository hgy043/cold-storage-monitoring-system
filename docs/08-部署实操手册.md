# 08-部署实操手册：Ubuntu 虚拟机 + gec6818 板卡

> 面向**阶段验收真机部署**：一台 Windows 开发机 + 一台 Ubuntu 虚拟机（边缘网关）+ 一块 gec6818 板卡（设备端）。
> 本文给出每一步"在哪台机器、用什么命令、编译/传输/运行什么"，按顺序执行即可。
> 项目在虚拟机上的假设路径：`/home/gec/iot/`（内含 `冷库监控系统/` 与 `huaweicloud-iot-device-quickstart/`，可自行调整）。

## 1. 部署拓扑与"谁在哪儿编译/运行"

```
[Windows 开发机]  源码编辑、可选跑大屏验证
      │  (桥接网络, 同网段)
      ▼
[Ubuntu 虚拟机 x86-64]  ── 192.168.x.10 ──▶  [gec6818 板卡 ARM]  192.168.x.20
  ├─ gateway/   边缘网关(C + 华为SDK)     ▲  device/      设备端采集上报
  ├─ web/       H5 大屏后端(可选)          │  device/ui/   LVGL 板端界面
  ├─ node-gateway/  Node网关(可选)
  └─ tools/     模拟设备(无板子时验证)
```

| 程序 | 编译环境 | 运行环境 | 说明 |
|---|---|---|---|
| `gateway/` C 网关 | Ubuntu 虚拟机（x86-64 gcc + 华为 SDK） | Ubuntu 虚拟机 | SDK 的 `libHWMQTT.so` 是 **x86-64**，板子跑不了 |
| `web/` 大屏后端 | 任意（Node ≥18） | Ubuntu 虚拟机 | 内嵌 MQTT broker + REST + WS |
| `node-gateway/` | 任意（Node ≥18） | Ubuntu 虚拟机 | 与 C 网关二选一；本地明文演示用 |
| `device/` 设备端 | Ubuntu 虚拟机（**交叉编译**） | **gec6818 板卡** | 产物 `device` 传板子 |
| `device/ui/` LVGL 界面 | Ubuntu 虚拟机（**交叉编译**） | **gec6818 板卡** | 产物 `coldstorage_ui` 传板子 |
| `tools/simulate_devices.js` | 任意 | Ubuntu 虚拟机 | 无板子时验证链路的模拟器 |

## 2. 第 0 步：网络与 IP 规划

1. 虚拟机网络模式选**桥接**（与 Windows/板子同网段），或虚拟机-板子直连网线（配 192.168.1.x）。
2. 固定各机器 IP（示例）：Windows 192.168.x.5 / Ubuntu 虚拟机 192.168.x.10 / 板子 192.168.x.20。
3. 互通验证：
   ```bash
   # Ubuntu 虚拟机
   ip addr                     # 确认 IP
   ping 192.168.x.20           # 通板子
   # 板子串口/SSH 终端
   ifconfig eth0               # 确认 IP
   ping 192.168.x.10           # 通虚拟机
   ```

## 3. 第 1 步：Ubuntu 虚拟机环境准备

```bash
# 基础工具
sudo apt update
sudo apt install -y gcc make net-tools git ssh
# 交叉编译工具链（用你板子配套的，二选一；gec6818 教程常见 arm-linux-gcc）
sudo apt install -y gcc-arm-linux-gnueabihf     # 方案A：apt 硬浮点工具链
# 方案B：把老师/厂商给的 arm-linux-gcc 解压到 /usr/local/arm/ 后加入 PATH：
export PATH=/usr/local/arm/arm-2014.05/bin:$PATH   # 示例，按实际路径
arm-linux-gcc -v                                  # 验证可用
# Node.js（跑 web / node-gateway / 模拟器）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
node -v

# 放置项目（保持相对路径：SDK 与 冷库监控系统 同级）
mkdir -p /home/gec/iot
# 从 Windows 拷贝整个 "deepseek harness" 目录到 /home/gec/iot/（scp / U盘 / 共享文件夹皆可）
ls /home/gec/iot/
# 预期看到: 冷库监控系统/  huaweicloud-iot-device-quickstart/  项目介绍及流程框架.md

# 验证华为 SDK 库架构（应为 x86-64）
file /home/gec/iot/huaweicloud-iot-device-quickstart/lib/libHWMQTT.so
# ELF 64-bit LSB shared object, x86-64
```

## 4. 第 2 步：边缘网关（Ubuntu 虚拟机，x86-64）

### 4.1 修改网关配置
```bash
cd /home/gec/iot/冷库监控系统/gateway
vi ClientConf.json
# 接华为云（验收如用真实云）：改成你的 deviceId/secret/serverUri
#   {"deviceId":"...","secret":"...","serverUri":"ssl://xxxx.iotda-device.cn-south-4.myhuaweicloud.com:8883",
#    "tcpPort":18830,"reportIntervalMs":2000,"subDeviceIdPrefix":"","defaultAlarmThreshold":-20}
# 本地演示（无云账号）：不改，直接跑 node-gateway + web（见 4.3 备注）
```

### 4.2 编译并运行 C 网关
```bash
cd /home/gec/iot/冷库监控系统/gateway
./start.sh          # 内部：LD_LIBRARY_PATH=../huaweicloud-iot-device-quickstart/lib + make + ./gateway
# 预期日志（接华为云）：
#   AgentLite: handleConnectSuccess(), login success
#   网关启动完成 / TCP 服务已监听端口 18830
```
> 手动执行等价：`export LD_LIBRARY_PATH=../huaweicloud-iot-device-quickstart/lib/ && make && ./gateway`
> 若连华为云失败：检查 deviceId/secret、`ssl://` 地址与 8883 端口出网、rootcert.pem 在 SDK `conf/` 下。

### 4.3 （推荐）本地演示模式：Node 网关 + 大屏
无云账号验收时，网关层用 Node 版（同协议），云层用 web 内嵌 broker，全程离线：
```bash
cd /home/gec/iot/冷库监控系统/node-gateway && npm install && node gateway.js &
cd /home/gec/iot/冷库监控系统/web && npm install && node server.js &
# 大屏: http://<虚拟机IP>:8080
```
> **有板子时**：板子 device 连的 TCP 端口 18830 在虚拟机——Node 网关或 C 网关都监听它，二选一即可。

## 5. 第 3 步：gec6818 板卡（ARM）

### 5.1 板子系统确认
```bash
# 板子串口终端
uname -a                    # 应为 Linux ... armv7l（32 位用户态）
ls -l /dev/fb0              # LVGL 界面需要 framebuffer（7寸屏驱动已加载则存在）
ls /dev/input/              # 触摸设备（event0 等，evtest 可查）
ping 192.168.x.10           # 通虚拟机
```

### 5.2 交叉编译设备端 device（在 Ubuntu 虚拟机执行）
```bash
cd /home/gec/iot/冷库监控系统/device
make clean
# 用你板子的工具链名覆盖 CC（arm-linux-gcc 或 arm-linux-gnueabihf-gcc）
make CC=arm-linux-gcc          # 或 make CC=arm-linux-gnueabihf-gcc
file device                     # 应为 ELF 32-bit ARM executable
```
> 若板子库不全导致运行报错（找不到 libpthread.so.x），可静态链接：
> `make clean && make CC=arm-linux-gcc CFLAGS="-Wall -O2 -static"`

### 5.3 交叉编译 LVGL 界面 coldstorage_ui（在 Ubuntu 虚拟机执行）
```bash
cd /home/gec/iot/冷库监控系统/device/ui
make                     # 默认 CC=arm-linux-gcc（与你的 LVGL 移植工程一致）
# 若工具链名字不同：make CC=arm-linux-gnueabihf-gcc
file coldstorage_ui      # ELF 32-bit ARM executable
```
> LVGL 移植工程（`lvgl_linux_framebuffer-9`）也要拷到虚拟机，Makefile 里 `LVGL_ROOT` 指向它的相对路径即可。

### 5.4 把程序传到板子（三选一）

**方式 A：scp（板子需运行 ssh 服务 dropbear/openssh）**
```bash
# Ubuntu 虚拟机
scp device device.conf root@192.168.x.20:/root/
scp device/ui/coldstorage_ui root@192.168.x.20:/root/
```

**方式 B：tftp（虚拟机起 tftpd，板子 tftp 拉取）**
```bash
# Ubuntu 虚拟机
sudo apt install -y tftpd-hpa
sudo cp device /srv/tftp/ && sudo cp device.conf /srv/tftp/ && sudo cp coldstorage_ui /srv/tftp/
# 板子
cd /root
tftp -g -r device 192.168.x.10
tftp -g -r device.conf 192.168.x.10
tftp -g -r coldstorage_ui 192.168.x.10
```

**方式 C：SD 卡（TF 卡槽）**
把 `device`、`device.conf`、`coldstorage_ui` 拷到 FAT 格式 TF 卡，插入板子：
```bash
mkdir -p /mnt/sd && mount /dev/mmcblk0p1 /mnt/sd
cp /mnt/sd/device* /mnt/sd/coldstorage_ui /root/
```

### 5.5 板子配置与运行
```bash
cd /root
chmod +x device coldstorage_ui

# 改配置：网关 IP 指向 Ubuntu 虚拟机；无传感器时保持 sim_mode=1
vi device.conf
#   gateway_ip=192.168.x.10     ← 必改（原来是 127.0.0.1）
#   node_id=cold01_front        # 每块板子一个节点，按需改
#   sim_mode=1                  # 1=模拟数据；0=真实 sysfs 传感器/GPIO

# 运行设备端（前台观察日志）
./device
# 预期：已发送注册帧 node_id=cold01_front ... 周期上报 data
```

**同时跑 LVGL 界面（独立进程，或与 device 分开演示）：**
```bash
./coldstorage_ui cold01_front -20
# 屏上出现冷库监测界面；触摸可点按钮（按钮动作在独立演示模式下打印日志）
```

**当前验收运行方式（任务改动.txt：gec6818 = 终端 + 报警设备，不跑 device 采集，直接连转发程序）：**
```bash
# ① Ubuntu 先启动虚拟数据转发程序（连华为云 + 监听 18830）
cd /home/gec/iot/冷库监控系统/virtual-server && node virtual_bridge.js
# 预期日志：MQTT 已连接 ... TCP 服务监听 18830

# ② 板子上直接运行终端（参数 = 转发程序IP 冷库名 编号 阈值）
cd /root && chmod +x coldstorage_ui
./coldstorage_ui 192.168.x.10 1号冷库 NO.001 -20
# 预期：顶栏"在线"变绿，4 温区数据每 3s 刷新；每 30s 报警 → 蜂鸣 + LED → 触摸"取消报警"停止
```
> 说明：当前验收**不需要** `device` 采集进程与网关——Ubuntu 转发程序直接对接华为云虚拟数据并推给终端。
> 二合一集成（界面+采集+上云同一进程）见 `device/ui/README.md` 的集成指引。

## 6. 第 4 步：联调验证

**当前验收链路（virtual_bridge + gec6818 终端，任务改动.txt）**
```
华为云 IoTDA(yihao) ←MQTT← Ubuntu virtual_bridge.js(每3s/每30s报警) ──TCP:18830 virt_data──▶ gec6818 终端
```
1. 转发程序日志：`MQTT 已连接`、`推送虚拟数据, 报警=0`（每 30s 一条）、`收到报警确认`
2. 终端顶栏"在线"绿点；实时监测页趋势图滚动；报警时蜂鸣响、LED 亮、底栏"紧急"报警
3. 触摸"取消报警"→ 蜂鸣停止，转发程序日志出现"收到报警确认"
4. 华为云控制台可下发 confirm_alarm / set_beeper / set_led / set_alarm_threshold，终端执行并回 ack

**有板子（历史网关链路）**
```
板子 device ──TCP:18830──▶ 虚拟机 gateway(C 或 Node) ──MQTT──▶ 华为云 / web 内嵌 broker ──▶ 大屏
```
1. 虚拟机网关日志出现：`设备上线 node_id=cold01_front` + 周期性 `批量上报`
2. 大屏（`http://<虚拟机IP>:8080`）出现 cold01 卡片数据实时刷新
3. 点"LED 开"：网关日志 `收到命令→已下发 TCP 命令→命令回执 success→已发布命令响应`，板子终端显示收到 cmd 帧

## 8. 常见问题

| 现象 | 排查 |
|---|---|
| 板子 ping 不通虚拟机 | 网段/掩码、虚拟机桥接 vs NAT、网线直连时对端 IP 配置 |
| 交叉编译报找不到头文件 | 确认用的工具链是板子配套版本；`arm-linux-gcc -v` 看 sysroot |
| 板子运行报 `not found` | 动态库缺失 → 静态链接（CFLAGS 加 -static）；或确认 `chmod +x` |
| 板子 `/dev/fb0` 不存在 | 屏驱动未加载，先解决显示环境再跑 LVGL |
| LVGL 触摸没反应 | `evtest` 找触摸事件设备，改 `lv_drv_conf.h` 的 `EVDEV_NAME` |
| 网关连华为云失败 | deviceId/secret 大小写、`ssl://` 地址、8883 出网、证书在 `conf/rootcert.pem` |
| 大屏断网白屏 | ECharts 已本地化（`web/public/vendor/echarts.min.js`），不受影响 |
