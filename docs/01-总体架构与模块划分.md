# 01-总体架构与模块划分

> 对应《项目介绍及流程框架.md》的四层架构：感知执行层 / 边缘计算层 / 云平台层 / 应用展示层。
> 本项目交付的可运行代码覆盖四层，并提供一个"本地演示模式"（Node 网关 + 内嵌 MQTT broker），
> 让整套链路在没有华为云账号时也能在本机跑通；正式部署时切换到 C 网关 + 华为云 IoTDA。

## 1. 分层与模块

| 层 | 运行位置 | 交付物 | 说明 |
|---|---|---|---|
| 感知执行层 | gec6818 开发板（或 PC 模拟） | `device/`（C 程序） | 温湿度采集、LED/蜂鸣器控制；TCP 客户端接入网关 |
| 感知执行层（界面） | gec6818 开发板 7 寸屏 | `device/ui/`（LVGL v9，800×480 多页面触摸 SCADA） | **当前验收：终端 + 报警设备**——主菜单/实时监测/温区总览/设备控制/能耗与设置 5 页；报警时 /dev/beep 蜂鸣 + LED，巡查确认后停止 |
| 边缘计算层（当前验收） | Ubuntu 服务器 | `virtual-server/virtual_bridge.js`（Node 转发程序） | **虚拟数据源 + 转发器**：每 3s 生成 4 温区数据上报华为云设备 yihao，每 30s 制造报警，经 TCP:18830 推 virt_data 帧给 gec6818 终端，接收 confirm/ack |
| 边缘计算层 | Ubuntu 服务器 | `gateway/`（C + 华为 AgentLite SDK） | TCP 服务端聚合设备数据；MQTT 上报华为云；云端指令转 TCP 下发 |
| 边缘计算层（演示/跨平台） | 任意有 Node 的机器 | `node-gateway/`（Node.js） | 与 C 网关完全相同的 TCP 协议和 MQTT 主题语义，用于本机演示与协议教学 |
| 云平台层 | 华为云 IoTDA 或本地演示 broker | 配置文档 `04-华为云平台配置指南.md`；演示用 `web/server.js` 内嵌 aedes MQTT broker | 设备接入鉴权、数据存储、命令/属性下发、规则引擎告警 |
| 应用展示层 | 浏览器（B/S） | `web/public/`（H5 + ECharts + WebSocket） | 冷库监测卡片、曲线图、柱状图、下发控制按钮、事件日志 |

## 2. 两条业务闭环

- **上行**：gec6818 采集 → TCP 帧 → 网关解析 → 聚合后 MQTT 上报（子设备属性上报）→ broker/华为云 → Web 后端订阅存储 → WebSocket 推送 → H5 渲染。
- **下行**：H5 按钮 → REST → Web 后端 → MQTT 命令下发（`request_id` 关联）→ 网关订阅收到 → TCP 帧下发 → gec6818 执行 → TCP ack 回网关 → 网关 MQTT 命令响应回云端 → 后端记录结果并推送到 H5。

> **当前验收链路（任务改动.txt，与上述多设备网关链路并存）**：
> 华为云 IoTDA（设备 yihao）← MQTT 属性上报 ← Ubuntu `virtual_bridge.js`；后者同时经 TCP:18830 下发
> **virt_data 帧**（每 3s 虚拟数据 / 每 30s 报警）→ gec6818 终端（LVGL 显示 + 蜂鸣/LED）；
> 巡查确认 → 终端发 **confirm 帧** → 转发程序复位报警。详见 docs/02 §4.3/4.4、docs/05 §A。

```
│   └── ui/          # gec6818 板端 LVGL 界面（多页面触摸版）
├── gateway/         # Ubuntu 边缘网关 C 程序（基于 huaweicloud-iot-device-quickstart 的 AgentLite SDK）
├── node-gateway/    # Node.js 网关（跨平台演示，协议同 C 网关）
├── web/             # Node 后端（内嵌 aedes MQTT broker + REST + WebSocket + 数据存储）+ H5 大屏
├── virtual-server/  # Ubuntu 虚拟数据转发程序（当前验收：每 3s 数据/每 30s 报警 → 华为云 + gec6818 终端）
├── tools/           # 模拟设备工具（simulate_devices.js）、TCP 调试工具（tcp_probe.js）
└── scripts/         # 一键启动（start-all.bat/sh）、自动验证（verify-demo.js / verify-fixes.js）
```

## 4. 设备规模

演示规模：16 个冷库 × 前/后 2 个监测节点 = 32 个子设备。
节点命名：`cold01_front`、`cold01_back`、…、`cold16_front`、`cold16_back`。
